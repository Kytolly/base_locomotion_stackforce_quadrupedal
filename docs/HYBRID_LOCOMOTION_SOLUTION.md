# Hybrid Locomotion 解决方案

> **适用边界：** 本文是独立 108D Hybrid 任务的方案文档，不是当前 `E0-v1-46d` 主线实现。E0 Actor 保持 46D，不读取本文的接触、足端或前视地形观测；当前训练设计见 [TRAINING_DESIGN.md](TRAINING_DESIGN.md)。

## 目标

训练一个策略，使其在保持四维高层 command 不变的前提下，直接控制轮腿机器人完成平地行走、轮式滚动、stepping 和低台阶越障。策略应根据 command、本体状态、接触状态和地形信息自行选择轮腿协同方式，并连续完成混合 locomotion。

验收对象是策略的行为能力，不是某个预先指定的 gait。策略必须能够在轮式推进有效时利用轮子，在轮子推进不足或地形需要时抬腿、摆腿、重新落足并保持机身稳定。

## 设计约束

高层 command 固定为四维，顺序不可改变：

```text
[forward_velocity, lateral_velocity, yaw_rate, body_height]
```

这四维只表达机身运动意图，不编码具体腿序。系统不增加 `gait_profile`、`walk/trot/step` 模式、每条腿的摆动相位或显式 gate switch。这样可以验证策略是否从状态和地形中自主产生 hybrid locomotion，而不是由上层模式选择器切换人工控制器。

策略输出仍为现有 12 维动作：8 个腿部关节位置目标和 4 个轮关节速度目标。轮腿协同、支撑腿选择、摆腿时序、足端 clearance、落足位置和重心转移都由策略输出隐式决定。

## 策略输入合同

四维 command 本身不是越障状态描述。Actor 输入固定扩展为 108 维，保留原有 46 维并追加接触、腿端/轮心状态和前视地形采样。最终排列如下：

| 区间 | 维度 | 内容 |
| --- | ---: | --- |
| `[0:4]` | 4 | command：前向速度、横向速度、偏航角速度、机身高度 |
| `[4:34]` | 30 | 机体角速度、投影重力、12 个主动关节位置和速度 |
| `[34:46]` | 12 | 上一控制步动作 |
| `[46:50]` | 4 | 接触标志，顺序 `FR, FL, RL, RR` |
| `[50:54]` | 4 | 法向接触力，顺序 `FR, FL, RL, RR` |
| `[54:66]` | 12 | 腿端/轮心相对位置，按腿排列，每条 `x, y, z` |
| `[66:78]` | 12 | 腿端/轮心相对速度，按腿排列，每条 `vx, vy, vz` |
| `[78:93]` | 15 | 前视地形相对高度 |
| `[93:108]` | 15 | 前视地形有效位 |

### 接触定义

当前闭链 USD 中每个 `FR/FL/RL/RR_Foot_Link` 同时承载对应轮关节，没有独立的足底刚体。因此 Actor 不接收一个虚构的“腿脚接触”信号，而接收四个腿端/轮心承载点的接触状态和法向力：

```text
contact_flag = [FR, FL, RL, RR]
normal_force = [FR, FL, RL, RR]
```

仿真接触传感器读取对应 `Foot_Link` 的法向接触力。接触标志定义为 `F_normal > 1.0 N`，并使用 3 个仿真步的多数滤波。法向力裁剪并归一化为：

```text
normal_force_i = clip(F_normal_i / 20.0 N, 0, 1)
```

切向力用于滑移指标和训练日志，第一版不进入 Actor。若真实机器人增加独立足底压力传感器，必须作为新版本合同单独加入，不能覆盖当前轮端承载点语义。

### 腿端/轮心状态

状态使用机身 yaw 对齐坐标系：`x` 为左右方向，`y` 为机器人前进方向，`z` 向上。每条腿的末端状态顺序固定为：

```text
FR: px py pz vx vy vz
FL: px py pz vx vy vz
RL: px py pz vx vy vz
RR: px py pz vx vy vz
```

仿真由 `Foot_Link` 刚体位姿和速度转换到 base frame。真实机器人由关节编码器、关节速度和 IMU 姿态通过正运动学与速度雅可比估计；仅有 PCA9685 PWM 目标而没有位置回读时，不得把目标角度当作已测量末端状态。

### 前视地形射线合同

使用独立的前视 RayCaster，射线起点为 base frame 的 `(0, 0, 0.35 m)`，方向为 `(0, 0, -1)`。15 条射线采用固定的 3 列 × 5 行布局：

```text
x = [-0.30, 0.00, +0.30] m
y = [ 0.15, 0.35,  0.55, 0.75, 0.95] m
```

排列采用行优先顺序，从 `y=0.15 m` 到 `y=0.95 m`，每一行依次为左、中、右。每条射线输出相对 base 高度和有效位：

```text
h_i = clip((hit_z_i - base_z) / 0.30 m, -1, +1)
valid_i = 1 if hit is finite else 0
```

无效射线的 `h_i` 填 `0`，同时 `valid_i=0`。仿真与真实部署必须共享射线坐标、排序、裁剪范围和归一化；真实机器人使用前视深度相机或 3D LiDAR 生成同构的局部高度样本。

该 RayCaster 不替代当前用于支撑面估计的 `support_scanner`。后者继续用于 reward、termination 和评估指标；前视射线专门服务 Actor 的障碍预判。

### Critic 特权输入

Critic 可以继续使用仿真真值以改善训练，但 Actor 不得读取不可部署信息。推荐 Critic 额外使用：

- 精确足端接触点和法向力；
- 精确局部地形高度；
- base 线速度、支撑面高度和主动关节力矩；
- 地形生成参数仅用于训练稳定性，不作为 Actor 输入。

## Command 课程

扩大 command 范围是必要条件，但必须和地形难度、执行器随机化一起逐阶段提升。不能在固定困难地形上一次性放大所有范围。

| 阶段 | 前向速度 m/s | 横向速度 m/s | 偏航 rad/s | 机身高度 m | 地形 |
| --- | ---: | ---: | ---: | ---: | --- |
| C0 稳定起步 | 0.05--0.20 | -0.05--0.05 | -0.10--0.10 | 0.105--0.115 | 平地、轻微粗糙 |
| C1 轮腿混合 | 0.05--0.35 | -0.10--0.10 | -0.20--0.20 | 0.105--0.125 | 粗糙、坡面、浅波浪 |
| C2 stepping | 0.05--0.40 | -0.12--0.12 | -0.25--0.25 | 0.105--0.135 | 低台阶、正/反金字塔、washboard |
| C3 泛化 | 0.05--0.45 | -0.15--0.15 | -0.30--0.30 | 0.105--0.140 | 连续台阶、混合障碍和随机地形 |

每个阶段的 command 必须在 episode 内保持足够时间，使策略能完成一个或多个步态周期。command 变化率继续限幅，避免把 command 突变误认为 stepping 需求。阶段升级条件使用速度跟踪、存活率、接触有效率、轮腿动作分布和越障成功率的联合指标。

第四维不再固定为单一高度。它表达期望机身高度；策略应结合地形和支撑状态决定是否调整腿长、卸载轮端或改变重心。高度范围必须服从真实关节和闭链机构的可达性扫描。

## 域随机化

除 command 随机化外，训练必须随机化会改变 hybrid locomotion 决策的因素。随机化应有边界、有课程阶段，并在验证中分别报告 nominal 和 randomized 结果。

### 物理和执行器

- 机身、腿段和轮子的质量与质心；
- 关节刚度、阻尼、摩擦、执行器响应延迟和动作保持时间；
- 关节位置零偏、轮子半径和轮关节方向；
- 接触摩擦、恢复系数和接触求解扰动；
- 控制周期、观测延迟、动作噪声和观测噪声。

### 地形和初始状态

- 障碍高度、宽度、间距和前后顺序；
- 台阶起始距离、坡度、washboard 相位和粗糙度；
- 地形局部摩擦和高度测量缺失；
- 初始 base 高度、pitch/roll、横向偏移和初始轮腿接触组合。

### 随机化边界

随机化不能破坏任务可行性，也不能把训练变成无意义的跌倒采样。每个阶段必须保留一组固定 nominal environments，用于比较策略是否真的学到稳定行为。训练记录每个 episode 的随机化参数或摘要，验证报告按 terrain family 和随机化等级聚合。

## Reward 和训练目标

保留 command tracking 作为主目标，同时加入能区分“轮子滚动”和“腿部 stepping”的行为约束。奖励不是给定 gait 的监督标签。

### 必保留

- 前向、横向和偏航速度跟踪；
- body height 跟踪；
- 沿 command 方向的有效推进；
- 姿态、低机身高度、关节限位、动作变化率和机械功率约束；
- base collision、过度倾斜和危险终止惩罚。

### 需要加入或校准

- 支撑接触保持：至少有足够支撑端时，惩罚无支撑状态；
- 足端接触转换：奖励有效 lift-off、swing、touchdown 和 contact relocation；
- 滑移和反向接触速度惩罚；
- 障碍前方 clearance 和落足可达性约束；
- 轮腿推进分解指标，用于日志和选择 checkpoint，不直接强迫固定轮腿比例。

接触相关奖励必须使用经过传感器和支撑估计验证的信号。不能用单纯关节位置周期性作为 stepping 奖励，也不能因为腿部运动幅度大就判定越障成功。

## Hybrid locomotion gate

不设置显式 locomotion profile gate。gate 只存在于评测，不存在于策略输入或控制逻辑中。

### Gate A：平地 forward locomotion

固定四维 command，策略在平地稳定前进；轮腿动作可以由策略自由组合。记录速度误差、轮速、腿端接触转换和 base 位移。

### Gate B：轮驱动受限

逐步降低轮子可用摩擦或轮动作上限，策略应在 command 不变时增加腿部支撑和 stepping 行为，并保持有限的正向速度。

### Gate C：stepping-only capability

轮动作强制为零，要求多个连续有效的 lift-off、swing、touchdown、contact relocation，并产生持续正向位移。该 gate 用于确认腿部 locomotion 能力，但不作为训练时的显式模式开关。

### Gate D：单台阶和连续障碍

在未知起始距离和随机障碍参数下，机器人必须完成台阶前接近、前后轮/足端越障和越障后恢复。连续楼梯要求逐级通过，不能只测一次碰撞后的弹跳。

每个 gate 同时报告：command tracking、前向位移、有效接触周期、轮腿功率分解、base tilt、base collision、失稳终止和 terrain clearance。视频只是可视证据，最终判定以轨迹和接触数据为准。

## 实施顺序

1. 固定四维 command 顺序和 action contract，新增接触、足端和局部地形观测，并更新 Actor/critic 维度合同。
2. 在平地和浅粗糙地形上完成 C0 训练，确认输入有效位、有限值和 command tracking。
3. 逐阶段扩大 command 范围和 body-height 范围，同时加入物理、执行器、观测和地形域随机化。
4. 加入接触转换、支撑、滑移和 clearance 指标，先作为日志，再逐步加入 reward。
5. 在 C2/C3 地形上训练完整 hybrid policy，保持 wheel-only、stepping-only 和 hybrid 对照评测。
6. 用五种 command、八类 terrain family、nominal/randomized seeds 和长时回放选择 checkpoint。
7. 录制训练地形、Plateau、Washboard、单台阶和连续楼梯视频，并将视频与 JSONL 轨迹、checkpoint SHA256 绑定。

## 成功标准

方案只有在以下条件同时满足时才算完成：

- 四维 command contract 未改变；
- Actor 能读取部署可获得的接触、足端和局部地形信息；
- command 范围按课程扩大，body height 不再固定；
- 物理、执行器、观测、地形和初始状态均有受控域随机化；
- 策略没有 locomotion profile 或显式 gate switching 输入；
- hybrid、stepping-only 和连续障碍评测均有可重复轨迹证据；
- 速度跟踪、稳定性、接触周期和越障成功率同时达到项目验收门槛。

当前 20k checkpoint 只能作为基线。它尚未证明上述策略输入和课程已经训练完成，也不能由一次成功的开环参考步态回放替代策略验收。
